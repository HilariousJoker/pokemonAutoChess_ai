## Shared mechanics (Read)
- Base default rule `evolutionRule = {type: COUNT, numberRequired: 3}` — `pokemon.ts:110–113`. A unit that never sets `evolutionRule` inherits it, including terminal units; `hasEvolution` (`pokemon.ts:170–172`) = `evolution !== DEFAULT || evolutions.length > 0` is what says a unit can evolve.
- `EvolutionManager.getHandler` picks the handler by rule type — `app/core/evolution-logic/evolution-manager.ts:30–50`. Divergent targets: `EvolutionHandler.getEvolution` calls `divergentEvolution(pokemon, player, ...extraArgs)` if present, else `pokemon.evolution` — `evolution-handler.ts:33–42`.
- `EvolutionManager.afterEvolve` — `evolution-manager.ts:75–107`: after any evolution it updates synergies, applies `OnEvolutionEffect`s of the evolved unit's passive (`:84–90`), then **for every board unit whose passive is COSMOG or COSMOEM, if the evolved unit's passive is neither**: `addMaxHP(10)`, `stacks++`, `tryEvolve` (`:92–103`), then re-tries the evolved unit (`:106`).
- Stat carry-over when a unit evolves/transforms: `carryOverPermanentStats` — `evolution-handler.ts:45–91` (maxHP, atk, def, speDef, speed, ap, luck deltas versus a fresh base instance; TM).

## COSMOEM (and the Cosmog path)
- **Declared (COSMOEM):** `evolution = DEFAULT`, `evolutions = [SOLGALEO, LUNALA]`, **`stacksRequired = 8`**; rule `STACK` with a `divergentEvolution` callback (arity 2), `hp = 220`, passive `COSMOEM`, plus an `onAcquired` override (`pokemon.ts:14863–14896`; rule `:14868`, callback `:14870`, `onAcquired` `:14881–14886`, stacks `:14880`, hp `:14887`). **Production stack requirement confirmed: 8** (the development snapshot declares 10 — see the comparison section).
- **Declared (COSMOG):** `evolution = COSMOEM`, rule `STACK`, `stacksRequired = 8`, `hp = 140`, passive `COSMOG` (`pokemon.ts:14845–14861`).
- **Read — Cosmog to Cosmoem:** Cosmog's stacks come from `afterEvolve`: whenever a unit with a passive other than COSMOG/COSMOEM evolves, each COSMOG/COSMOEM on the board gets `addMaxHP(10)`, `stacks++` and a `tryEvolve` (`evolution-manager.ts:92–103`). `StackEvolutionHandler.canEvolve` then needs `stacks >= 8`, on board, no Eviolite (`stack-evolution-handler.ts:7–11`). `evolve` → `player.transformPokemon(cosmog, COSMOEM)`: new instance from the factory, `carryOverPermanentStats` (maxHP delta vs a fresh Cosmog is applied through `applyStat(HP)` → `addMaxHP`, `pokemon.ts:298–328, 387–390`), items re-added with `addItem`, then `newPokemon.onAcquired(this)` — `player.ts:333–352`.
- **Read — `Cosmoem.onAcquired`:** sets `stacks = -1`, `hp -= 10`, `hp -= 80`, `maxHP = hp` (`pokemon.ts:14881–14886`; comment: "revert hp buffs of cosmog"). In the plain case traced here — exactly 8 Cosmog buffs of +10 and no other maxHP changes, no items — the sequence is 220 (factory) + 80 (carried) = 300, then −90 → **210**.
- **Not claimed:** a universal acquired HP. The 210 holds only for that plain case. It is **unresolved** how it changes with (a) items added by `transformPokemon` *before* `onAcquired` (`player.ts:342–347`) whose `addItem` effects could change HP, (b) other permanent HP modifiers carried by `carryOverPermanentStats`, (c) Cosmog having fewer/more than 8 buffs at evolution, and (d) `onAcquired` being run by other acquisition paths (`rooms/game-room.ts:1418,1424,1609,1613`; `services/gift-shop.ts:75,105,178`) for a Cosmoem that never carried the Cosmog buffs, where the −90 would apply to a different starting value. The bare factory Cosmoem HP (220) is the only HP value this data asserts.
- **Read — Cosmoem to Solgaleo/Lunala:** the callback returns `SOLGALEO` when the unit stands on `(player.lightX, player.lightY)` **and** the player has some Light synergy tier effect (`SynergyTiers[Synergy.LIGHT].some(e => player.effects.has(e))`), else `LUNALA` (`pokemon.ts:14870–14878`). `afterEvolve` also gives a Cosmoem on board `stacks++`/`+10 maxHP` for later evolutions of other units, so a Cosmoem set to `-1` on acquisition needs further triggers to reach 8.
- **Unresolved:** what sets `lightX/lightY` and `effects` for a real player (`player.ts:191–192, 248–255` only show initialization); the `board.forEach` in `afterEvolve` runs while a Cosmog is replaced on the same board, so whether the new Cosmoem is visited by the same loop (what the `-1` comment implies) depends on `MapSchema` iteration semantics — not resolved; the combat-side `addStack` path (`pokemon-entity.ts:1803–1825`) for Cosmog/Cosmoem; Solgaleo/Lunala themselves.
